Indonesia Weather Data Pipeline

A daily, fully automated pipeline that collects weather data for 10 Indonesian cities, models it into a tested warehouse, and serves it in a live dashboard. It runs entirely on free tiers.

The problem

In retail and F&B, weather drives store traffic and demand: rainy days change what and how much customers buy. To use weather in sales analysis or demand forecasting, you first need a reliable, clean, always-up-to-date weather dataset. This project builds that dataset the way a production pipeline should: automated, idempotent, tested and monitored.

What I built

  • Python extractor with exponential-backoff retries, a one-time historical backfill, and daily incremental loads.
  • Raw layer in Postgres: API values stored untouched as JSONB, plus a run log (status, row counts, errors) for every run.
  • dbt project (raw → staging → marts): a daily fact table, city dimension, monthly climate summary, temperature anomaly detection (z-score vs. each city's monthly normal), and pipeline-health models.
  • Data quality: uniqueness, not-null, referential-integrity and value-range tests, plus source freshness alerts.
  • Orchestration and CI with GitHub Actions: a daily schedule, a manual backfill button, and linting, unit tests and dbt validation on every push.
  • Streamlit dashboard with city trends, a city comparison, anomalies, and a pipeline-health page.

Key design decisions

Idempotent loads

Every write is an upsert on (city, date). Re-running any load never creates duplicates, and unchanged rows are skipped, so each run reports exactly what was new or revised.

Late & revised data

Archive data arrives about 5 days late and can be revised, so each daily run re-reads a 10-day window. Days that aren't available yet are skipped and picked up later.

Raw stays raw

All typing and business logic lives in dbt, so it is versioned, tested and documented, and history can be re-modelled without calling the API again.

Fail loudly

One failing city doesn't block the others, but the run is marked as a partial failure and the job turns red, so problems are never silent.
