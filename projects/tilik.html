Tilik: Procurement Analytics Dashboard

A full-stack web app for procurement teams. It shows spend by category, weekly commodity prices with automatic alerts and a 4-week forecast, and vendor scorecards. A "Tanya Data" (ask your data) assistant answers questions in plain language using numbers queried from the database. The name comes from the Indonesian menilik, "to look closely".

The problem

Procurement data usually lives in purchase-order exports and spreadsheets. Answering everyday questions, like "why did raw-material spend jump this month, which commodity prices are rising, and which vendors keep delivering late?", means manual pivots that are slow and easy to get wrong. Tilik turns raw PO files into a validated database and answers those questions on one screen, with an AI assistant that is only allowed to quote numbers the database actually returned.

What it does

Spend analysis

KPIs against the previous period, 12-month trends and drill-down by category, with spend changes decomposed into volume vs price effects. An "Explain with AI" button writes a short narrative from that table.

Commodity prices

Weekly weighted-average prices with unit normalization, week-on-week change, automatic spike alerts and a 4-week linear-regression forecast with a 95% uncertainty band.

Vendor scorecard

A weighted score (40/35/25 by default) that recalculates instantly when the weights change, labels for problem vendors, and detection of possible split POs: several small orders, same vendor and day, adding up past the approval limit.

Tanya Data (ask your data)

Plain-language questions are routed to one of 7 parameterized query tools through a JSON schema. The answer can only use numbers the backend returned, and every answer shows the tool and parameters it used.

Safe imports

CSV uploads are previewed first, with an error and reason for every bad row (wrong dates, "Rp 315.000"-style numbers, unknown units). Valid rows commit in one transaction, and any batch can be rolled back.

Roles, export & settings

Viewer, Data Admin and IT Admin roles (argon2 passwords, HttpOnly session cookies), Excel export that follows the active filters, and editable master data, thresholds and weights.

Key design decisions

  • The AI never invents numbers: it picks a query tool and writes the summary, but the backend checks every number in the answer against the query result before showing it.
  • No API key needed: the backend runs a logged-in Claude Code (or Codex) CLI as a subprocess. If no CLI is found, a rule-based mock with the same JSON shape keeps the app usable.
  • Imports are reversible: each upload is one transaction tagged with a batch ID, so a rollback restores the KPIs exactly. This is covered by an integration test.
  • Logic you can test: unit normalization, weighted averages, decomposition, scoring, anomaly detection and forecasting are pure functions with their own unit tests.

Filters, imports, settings, export and free-text questions need the full app. The interface is in Indonesian.

What I learned

The hard part of an AI analytics assistant isn't the model, it's the guardrails. Constraining it to typed query tools and verifying its numbers on the server makes its answers something people can check, instead of something they have to trust.

All data in this project is dummy data from a generator script. No real company data is used.
